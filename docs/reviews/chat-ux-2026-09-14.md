## Current architecture

| Area                | Active implementation                                                                                                                    |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Runtime             | Next.js App Router 15.5.23 from lockfile, React 18.3.1, TypeScript                                                                       |
| Routes and language | `app/[locale]`, `next-intl`, Persian RTL and English LTR                                                                                 |
| Auth boundary       | Middleware and chat page guards, HTTP-only access/refresh cookies; BFF routes under `/api/app/*`                                         |
| Backend access      | `lib/server/backend-fetch.ts`, server-only `BACKEND_ORIGIN`, automatic refresh in `with-refresh.ts`                                      |
| Server state        | TanStack Query; conversation lists and details keyed by `['chats']` / `['chat', id]`                                                     |
| Chat orchestration  | `ChatShell` owns draft, lazy creation, edit/regenerate, stop and progressive answer display                                              |
| Send lifecycle      | `useSendMessage` inserts/reuses an optimistic UUID user message, handles acknowledgement, answer cache updates and failed/aborted states |
| Transport           | BFF WebSocket ticket, `/ws/chat/{id}/?ticket=...`, wait for `connected`, send `message`, UUID `client_message_id`, `think_level`         |
| Answer presentation | Backend supplies the answer in one frame; the hook reveals longer answers progressively with abort support                               |
| Message layout      | `MessageList` uses React Virtuoso; `MessageBubble` renders Markdown, tables, actions, feedback and sources                               |
| UI                  | Tailwind, Radix primitives, Motion, responsive auth/chat shells and shared providers                                                     |

The current send hook uses WebSocket only. README passages describing REST send as
the primary path and historical REST fallback guidance do not describe this
baseline. Old `.copy`/`.Copy` files and `repomix-output.xml` are not the active
implementation. No GitHub Actions workflow exists in this baseline.

## Findings and changes

| Reported issue                                               | Cause                                                                                       | Change                                                                                                                      |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Submitted text stays in composer                             | Draft cleared after the entire response promise finishes                                    | Clear accepted composer submissions before the first await; keep payload separately                                         |
| Failed first send could lose its text after moving the clear | Conversation creation may fail before any optimistic message exists                         | Restore that question if creation fails; keep existing failed-message retry/restore controls for later failures             |
| Retry/regenerate removes another draft                       | Successful completion unconditionally clears the composer                                   | Only explicit composer/suggested-prompt submissions consume the draft                                                       |
| Repeated loading phrases                                     | User bubble renders “sending” while the list independently renders assistant pending status | Keep one accessible assistant status; preserve the stable random phrase and hidden pending-user actions                     |
| Following message overlaps copy/edit                         | Absolutely positioned actions extend beyond the virtualized row's measured height           | Keep the actions in normal layout flow, including while transparent; allow wrapping                                         |
| Empty Persian caret starts on the left                       | Global `unicode-bidi: plaintext` leaves the empty paragraph without Persian direction       | Explicit locale direction for an empty composer, `dir="auto"` for typed text, local bidi override                           |
| Friendly-chat wording remains                                | Existing empty-state translation                                                            | Replace the sentence in both Persian and English                                                                            |
| University marks are too small                               | The original PNG has large transparent margins; nested padding reduces the mark further     | Shared logo presentation crops the transparent margins with CSS, uses larger responsive frames and a white contrast surface |

The original logo bitmap is preserved. Existing runtime dependency versions,
authentication code, backend routes and transport payloads are unchanged. Testing
Library and jsdom are development dependencies for DOM regression tests. Vitest
uses automatic JSX transformation for React component tests.

## Acceptance on the deployed preview

1. In Persian, focus the empty composer: the caret starts on the right. Type an
   English question and check automatic direction; clear it and check RTL again.
2. Send with Enter and the send button, in a new and an existing conversation.
   The composer clears immediately and only one pending phrase appears.
3. Stop during the wait and during answer reveal. The stop action completes and
   the submitted text does not reappear in the composer.
4. Simulate a creation failure: the first question is restored. Simulate a send
   failure: retry and restore remain available beside the failed question.
5. Keep an unrelated draft and retry/regenerate a previous message. The draft survives.
6. Inspect consecutive user messages, including short and multiline questions;
   hover or keyboard-focus copy/edit and check no overlap with the following row.
7. Check both university marks on auth and empty chat in light/dark themes and at
   360px, 390px, 768px and desktop widths. Confirm no clipping or horizontal overflow.
8. Confirm thinking-level persistence, suggested prompts, scrolling, Markdown tables,
   feedback and the English UI still work with the real backend.
